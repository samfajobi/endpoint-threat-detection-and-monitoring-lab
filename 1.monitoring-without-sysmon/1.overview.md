# 🖥️ Windows Endpoint Monitoring Using Native Event Logs (No Sysmon)

> A practical blue-team project demonstrating how to monitor a Windows 10/11 endpoint using **only built-in Windows Event Logs** — no Sysmon, no third-party agents.

---

# 🎯 Project Objective

Monitor and detect suspicious activity on a standalone Windows endpoint using:

* Security Log
* System Log
* Application Log
* PowerShell Operational Logs
* Advanced Audit Policy

This project demonstrates core SOC-level visibility using native Windows capabilities.

---

# 🧰 Lab Requirements

## Minimum Setup

* Windows 10 or Windows 11 (VM recommended)
* Local Administrator privileges
* Event Viewer access
* No domain required
* No Sysmon installed

---

# 📍 Step 1 — Enable Advanced Audit Policies

Open:

```
secpol.msc
```

Navigate to:

```
Security Settings
└── Advanced Audit Policy Configuration
    └── Audit Policies
```

Enable the following categories:

---

## 🔐 Logon / Logoff

* Audit Logon (Success, Failure)
* Audit Logoff
* Audit Special Logon

---

## 👤 Account Logon

* Audit Credential Validation

---

## 🛠️ Detailed Tracking

* Audit Process Creation
* Audit Process Termination

---

## 🧱 Object Access

* Audit File System
* Audit Registry

---

## 🛡️ Policy Change

* Audit Audit Policy Change
* Audit Authentication Policy Change

---

# 📍 Step 2 — Enable Command Line Logging

Open:

```
gpedit.msc
```

Navigate to:

```
Computer Configuration
└── Administrative Templates
    └── System
        └── Audit Process Creation
```

Enable:

```
Include command line in process creation events
```

This enhances Event ID 4688 visibility.

---

# 📍 Step 3 — Enable PowerShell Logging

Open:

```
gpedit.msc
```

Navigate to:

```
Computer Configuration
└── Administrative Templates
    └── Windows Components
        └── Windows PowerShell
```

Enable:

* Turn on PowerShell Script Block Logging
* Turn on PowerShell Module Logging

# 📊 Understanding Native Windows Log Locations

Open:

```
Event Viewer
```

---

## 🔐 Security Log

Path:
```
Windows Logs → Security
```

Used for:
* Logons
* Account activity
* Process creation
* Privilege use

---

## ⚙️ System Log

Path:
```
Windows Logs → System
```

Used for:
* Service starts/stops
* Driver loading
* System shutdown/reboot
* System errors

---

## 🧪 Application Log

Path:
```
Windows Logs → Application
```

Used for:
* Application crashes
* Software errors
* Application-specific logs

---

## 💻 PowerShell Operational Log

Path:
```
Applications and Services Logs
└── Microsoft
    └── Windows
        └── PowerShell
            └── Operational
```

Used for:
* Script execution visibility
* Encoded commands
* Script block contents

# 🔬 Practical Monitoring Tasks (Hands-On Scenarios)

---

## 🧪 Task 1 — Failed Login Detection

1. Attempt wrong password multiple times.
2. Open Security Log.
3. Filter for:
```
Event ID: 4625
```

Observe:
* Source IP
* Account name
* Logon type

---

## 🧪 Task 2 — Process Monitoring

Run:

```
cmd.exe
powershell.exe
notepad.exe
```

Check:

```
Event ID 4688
```

Observe:
* Parent process
* Command line
* Account used

---

## 🧪 Task 3 — Privilege Escalation Simulation

1. Create a new local user:
```
net user testuser Password123 /add
```

2. Add to Administrators:
```
net localgroup administrators testuser /add
```

Check:
* 4720
* 4732

---

## 🧪 Task 4 — PowerShell Execution Monitoring

Run:

```
powershell -ExecutionPolicy Bypass -Command "Get-Process"
```

Check:
* Event ID 4688
* Event ID 4104

---

## 🧪 Task 5 — Persistence Simulation

Create a scheduled task:

```
schtasks /create /sc minute /mo 5 /tn TestTask /tr notepad.exe
```

Check:
* Security log (Task creation)
* System log (Service interactions)

---

## 🧪 Task 6 — Service Installation Monitoring

Create a test service:

```
sc create TestService binPath= "C:\Windows\System32\notepad.exe"
```

Check:
```
System Log → Event ID 7045
```
