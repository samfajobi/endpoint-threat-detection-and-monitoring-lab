# 🖥️ Windows Endpoint Monitoring Using Native Event Logs (No Sysmon)

> A practical blue-team project demonstrating how to monitor a Windows 10/11 endpoint using **only built-in Windows Event Logs** — no Sysmon, no third-party agents.

---

# 🎯 Project Objective

Monitor and detect suspicious activity on a standalone Windows endpoint using:

* Security Log
* System Log
* Application Log
* PowerShell Operational Logs
* Advanced Audit Policy

This project demonstrates core SOC-level visibility using native Windows capabilities.

---

# 🧰 Lab Requirements

## Minimum Setup

* Windows 10 or Windows 11 (VM recommended)
* Local Administrator privileges
* Event Viewer access
* No domain required
* No Sysmon installed

---

# 📍 Step 1 — Enable Advanced Audit Policies

Open:

```
secpol.msc
```

Navigate to:

```
Security Settings
└── Advanced Audit Policy Configuration
    └── Audit Policies
```

Enable the following categories:

---

## 🔐 Logon / Logoff

* Audit Logon (Success, Failure)
* Audit Logoff
* Audit Special Logon

---

## 👤 Account Logon

* Audit Credential Validation

---

## 🛠️ Detailed Tracking

* Audit Process Creation
* Audit Process Termination

---

## 🧱 Object Access

* Audit File System
* Audit Registry

---

## 🛡️ Policy Change

* Audit Audit Policy Change
* Audit Authentication Policy Change

---

# 📍 Step 2 — Enable Command Line Logging

Open:

```
gpedit.msc
```

Navigate to:

```
Computer Configuration
└── Administrative Templates
    └── System
        └── Audit Process Creation
```

Enable:

```
Include command line in process creation events
```

This enhances Event ID 4688 visibility.

---

# 📍 Step 3 — Enable PowerShell Logging

Open:

```
gpedit.msc
```

Navigate to:

```
Computer Configuration
└── Administrative Templates
    └── Windows Components
        └── Windows PowerShell
```

Enable:

* Turn on PowerShell Script Block Logging
* Turn on PowerShell Module Logging

---

# 📊 Understanding Native Windows Log Locations

Open:

```
Event Viewer
```

---

## 🔐 Security Log

Path:
```
Windows Logs → Security
```

Used for:
* Logons
* Account activity
* Process creation
* Privilege use

---

## ⚙️ System Log

Path:
```
Windows Logs → System
```

Used for:
* Service starts/stops
* Driver loading
* System shutdown/reboot
* System errors

---

## 🧪 Application Log

Path:
```
Windows Logs → Application
```

Used for:
* Application crashes
* Software errors
* Application-specific logs

---

## 💻 PowerShell Operational Log

Path:
```
Applications and Services Logs
└── Microsoft
    └── Windows
        └── PowerShell
            └── Operational
```

Used for:
* Script execution visibility
* Encoded commands
* Script block contents

# 🔎 Key Event IDs to Monitor

---

## 🔐 Authentication & Logon Monitoring

| Event ID | Description |
|-----------|------------|
| 4624 | Successful logon |
| 4625 | Failed logon |
| 4634 | Logoff |
| 4648 | Logon using explicit credentials |
| 4672 | Special privileges assigned |

---

## 🛠️ Process Monitoring

| Event ID | Description |
|-----------|------------|
| 4688 | Process creation |
| 4689 | Process termination |

Focus on:
* powershell.exe
* cmd.exe
* wmic.exe
* rundll32.exe
* mshta.exe
* certutil.exe

---

## 👥 Account & Privilege Changes (Local System)

| Event ID | Description |
|-----------|------------|
| 4720 | User account created |
| 4726 | User account deleted |
| 4732 | Added to local Administrators group |
| 4740 | Account locked out |

---

## ⚡ PowerShell Monitoring

| Event ID | Description |
|-----------|------------|
| 4103 | Module logging |
| 4104 | Script block logging |
